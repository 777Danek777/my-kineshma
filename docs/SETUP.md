# Окружение и подготовка к запуску

> Этот документ сохраняет результаты первоначального аудита пустой папки. Сейчас уже работают Next.js, локальная PostgreSQL 18.7 и защищённая административная панель. Актуальные команды запуска — в [README.md](../README.md), инструкция владельцу — в [ADMIN.md](ADMIN.md), результат и проверки — в [STAGE-2.md](STAGE-2.md). Утверждения ниже об отсутствии приложения, базы и настроек относятся к первому осмотру и не являются текущей инструкцией запуска. Текущий адрес — `http://127.0.0.1:3000`; после перезагрузки нужны `npm.cmd run db:start` и `npm.cmd run dev`.

## Совместимость технологий

Проверено по официальной документации 26 ноября 2026 года. Предлагаемые линии для следующего этапа: Next.js 16, TypeScript 5.9, Tailwind CSS 4, Prisma 7, PostgreSQL 18. Это предложение для установки, а не уже установленные зависимости; точные версии зафиксируем в `package.json` и lock-файле при создании приложения.

Установленный Node.js 24.14.1 соответствует требованиям [Next.js](https://nextjs.org/docs/app/getting-started/installation) и [Prisma 7](https://www.prisma.io/docs/orm/v7/reference/system-requirements). Tailwind подключается по [официальной инструкции для Next.js](https://tailwindcss.com/docs/installation/framework-guides/nextjs). PostgreSQL 18 входит в [список поддерживаемых баз Prisma 7](https://www.prisma.io/docs/orm/v7/reference/supported-databases).

При установке важно явно выбрать Prisma 7: сейчас тег `latest` у CLI Prisma ведёт на предварительную Prisma 8 RC, а Prisma 7 остаётся поддерживаемой стабильной линией. Не смешивать CLI Prisma 8 с клиентом и схемой Prisma 7. Источник: [статус релизов Prisma](https://www.prisma.io/docs/orm/release-status).

До размещения в интернете отдельно проверим актуальные исправления безопасности выбранных версий. Совместимость установленного Node.js не заменяет эту проверку.

## Выбор локальной базы перед этапом 3

Предпочтительный вариант — PostgreSQL в Docker Compose: он ближе к будущему серверному окружению. Потребуется установить и настроить Docker Desktop, если его действительно нет. Альтернатива — установить PostgreSQL непосредственно в Windows; тогда проверку контейнерной сборки всё равно потребуется выполнить позднее. Эти сервисы в рамках подготовительного этапа не устанавливались.

## Настройки

`.env.example` — предварительный список настроек с пустой строкой подключения к базе. Это не готовая конфигурация. Реальный `.env` создадим при подключении базы и авторизации. Он исключён из Git. Параметры авторизации добавим после выбора библиотеки.

`APP_URL` будет адресом сайта: локально `http://localhost:3000`, на сервере — фактический домен с HTTPS. `DATABASE_URL` получим при создании базы. `UPLOAD_DIR` укажет на постоянное хранилище фотографий. Приложение пока не читает и не проверяет эти настройки.

## Как проверить подготовительный этап

Откройте папку проекта в VS Code: должны появиться `src`, `prisma`, `public`, `storage`, `deploy`, `scripts`, `tests`, `docs` и `README.md`. Структуру и план можно посмотреть прямо в редакторе.

Если хочется проверить установленный Node.js, в терминале PowerShell внутри VS Code выполните:

```powershell
Set-Location -LiteralPath 'C:\Projects\my-kineshma'
node --version
npm.cmd --version
git --version
```

В примерах используем `npm.cmd`, чтобы не зависеть от политики запуска PowerShell-скриптов. Команду запуска сайта предоставим после создания приложения.
