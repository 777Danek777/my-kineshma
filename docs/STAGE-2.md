# Этап 2: административная панель и публикации

## Результат

Локальный сайт подключён к PostgreSQL. Реализованы защищённый вход и выход, кабинет редакции, обзор, список с поиском и фильтром по статусу, создание, редактирование и удаление новостей, черновики, публикация и снятие с публикации, категории и загрузка изображений. Интерфейс адаптирован для узкого экрана и содержит подтверждения опасных действий, сообщения об ошибках и успешном сохранении.

Главная `/` показывает только опубликованные материалы из базы. Для новости создан маршрут `/news/[slug]`. Старый визуальный макет сохранён на `/demo`, с прежними явными пометками о демонстрационных текстах. Демо не подмешивается в настоящую ленту и счётчики админки.

Пошаговая инструкция владельцу — [ADMIN.md](ADMIN.md). Актуальный запуск — [README.md](../README.md).

## Хранение и локальный запуск

PostgreSQL доступен только через loopback. Исполняемые файлы находятся в `storage/postgres-runtime/pgsql/bin`, данные — в `storage/postgres-data`. Служба Windows не создавалась; после перезагрузки нужен `npm.cmd run db:start`. `npm.cmd run db:stop` останавливает базу без удаления данных.

Текущий `APP_URL` — строго `http://127.0.0.1:3000`. `.env` настроен локально и исключён из Git. Строку подключения и секрет авторизации нельзя копировать в документацию или сообщения. Приложение использует отдельную роль PostgreSQL, а не учётную запись суперпользователя базы.

Для существующей базы используются `db:migrate` и `db:seed`; сброс или повторная инициализация хранилища для запуска не нужны. Создан первоначальный администратор `admin@my-kineshma.local`; случайный пароль находится только в исключённом из Git локальном `storage/private/first-admin.txt`. Дополнительные аккаунты и смена пароля выполняются локальными командами `admin:create` и `admin:reset`.

## Защита и правила данных

- Каждая защищённая страница и layout проверяют администратора на сервере. Каждая административная API-операция отдельно проверяет сеанс и роль; скрытие кнопок не является защитой.
- Гостя страницы кабинета перенаправляют на вход. Подделанная cookie и аккаунт без роли администратора не дают доступ к административным данным.
- Публичная регистрация и публичные операции управления аккаунтом отключены. Роль администратора не принимается из формы входа или пользовательского запроса.
- Пароли хранятся в виде хеша. Сеансы хранятся на сервере; cookies имеют `HttpOnly` и `SameSite=Lax`, а при HTTPS — `Secure`. Выход отзывает сеанс, сброс пароля — все сеансы пользователя.
- Изменяющие запросы требуют правильный `Origin`; сторонние источники и cross-site запросы отклоняются. Ограничения попыток сохраняются в PostgreSQL и не обходятся подстановкой `X-Forwarded-For`.
- Административные ответы не сохраняются в общем кеше. Черновики и снятые материалы исключены из публичных запросов. Фото выдаётся посетителю только при наличии опубликованной новости с этим фото; остальное доступно администратору.
- Заголовок — 3–180 символов, категория обязательна, текст — до 50 000 символов. Для публикации требуется минимум 20 символов текста. HTML отображается как текст, а не исполняемая разметка.
- Изображения: JPEG/PNG/WebP, до 5 МиБ и 20 Мп, до 6 фото. Проверяется фактический формат; файлы перекодируются в WebP без исходных метаданных. SVG, неверный MIME и превышение лимитов отклоняются. Имена файлов генерирует сервер.
- Правки и удаление используют номер версии; устаревший запрос возвращает конфликт `409`, не перезаписывая новое состояние. Занятая категория не удаляется; названия категорий уникальны без учёта регистра.

## Проверки

Итоговые линтер и проверка TypeScript прошли без ошибок. Production-сборка выполнена без предупреждений; `npm audit` сообщил о 0 известных уязвимостей. Интеграционный сценарий `npm.cmd run test:admin` повторно прошёл все 23 группы проверок уже на production-сервере. Он создаёт отдельные временные аккаунты и данные, не использует пароль владельца, после работы удаляет свои записи и файлы.

Проверены остановка и повторный запуск PostgreSQL без потери данных. После всей очистки в базе осталось 1 администратор, 9 категорий, 0 публикаций и 0 медиа; первоначальный аккаунт сохранён. Сайт оставлен работающим через `npm.cmd run start` на `http://127.0.0.1:3000`. Для будущей разработки используются `db:start` и `dev`; серверы `start` и `dev` одновременно на порту 3000 не запускаются.

Проверены:

- перенаправления гостей, запрет всех административных API-операций без входа и отказ обычному пользователю;
- подделанные cookies, закрытая регистрация, атрибуты cookies, приватные ответы и отзыв сеанса при выходе;
- создание/переименование категорий, уникальность названий и запрет удаления занятой категории;
- допустимая загрузка и перекодирование изображения, отказ SVG, неверному формату и чрезмерному размеру;
- закрытость текста и фотографий черновика, серверная проверка полей, сохранение и чтение изменений;
- конфликты версий при редактировании и удалении;
- публикация с безопасным отображением потенциально вредоносного текста, публичная выдача опубликованного фото без кеша оптимизатора Next.js;
- снятие с публикации с закрытием страницы и изображения, удаление материала и освободившейся категории;
- запрет сторонних изменяющих запросов и сохраняемый в базе лимит входа.

В браузере на временном аккаунте проверены вход, загрузка фотографии, предпросмотр, сохранение черновика, сохранность записи после обновления списка, мобильный экран шириной 390 px и выход. Временные аккаунты, записи и изображения после проверки удалены. Тестовые публикации не оставлены в рабочей ленте.

## Что ещё не входит в готовый этап

Это локальное приложение, а не развёрнутый публичный сервис. Внешний сервер, домен, HTTPS и автоматический запуск ещё не настроены. `noindex` сохраняется. Перед публичным запуском понадобятся отдельная проверка серверного окружения и настройка резервных копий с проверкой восстановления.

Публичная главная пока загружает 100 последних опубликованных материалов. Для более крупного архива потребуется отдельная серверная пагинация; административный список уже поддерживает страницы.

Автоматического резервного копирования и плановой очистки неиспользуемых загрузок нет. Удаление новости не обещает физическое удаление всех ранее загруженных файлов: неиспользуемые файлы остаются закрытыми для посетителей. Git не содержит базу, изображения редакции и секреты; копия кода не заменяет копию данных.

Не реализованы предложка с модерацией, импорт/кросспостинг VK, восстановление пароля через письмо, публичная регистрация, форматирование HTML и история откатов редакций. Текстовый редактор работает с обычными абзацами. Демонстрационные материалы остаются только в отдельной демонстрации дизайна.
